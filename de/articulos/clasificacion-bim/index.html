      Das Problem

      Fünf Namen für dieselbe Wand.

      Jedes Büro, jede Software, jede Person benennt anders. Ohne gemeinsamen Code stimmen weder Mengen noch Suchergebnisse.

      Dasselbe Objekt, fünf Bezeichnungen
      Was passiert Niemand summiert dasselbe der Filter „Wände“ verfehlt die Hälfte
      Wo es schmerzt
      MengenermittlungSucheInstandhaltungAnforderungen
      Der Ausweg Ein Code aus einer gemeinsamen Tabelle der Name darf frei bleiben
      Definition

      Klassifizieren heißt sagen, was etwas ist.

      Ein Klassifikationscode gruppiert Objekte nach dem, was sie gemeinsam haben. Er sagt nicht, welches Objekt es ist oder wie es beschaffen ist.

      Vier verschiedene Angaben zu derselben Tür
      Was ihn nützlich macht Für alle gleich gleiches Objekt, gleicher Code, egal wer modelliert
      Was er nicht ist Ein Familienname den erfindet jedes Büro selbst
      Facetten

      Ein Objekt, mehrere Tabellen.

      Dieselbe Tür ist Teil eines Raums, ein Element mit einer Funktion, ein Produkt, das man kauft, und eine Leistung, die man ausführt. Jede Sicht hat ihre Tabelle.

      Eine Tür, fünf mögliche Codes
      Deshalb Facettiert mehrere unabhängige Tabellen, kombinierbar
      Die Frage jeder Tabelle
      • Wo ist es? · Raum
      • Was tut es? · Element oder System
      • Was wird gekauft? · Produkt
      Nicht alle sind nötig Nur die, die jeder Zweck verlangt
      Hierarchie

      Ein Code liest sich vom Allgemeinen zum Konkreten.

      Jedes Ziffernpaar führt eine Ebene tiefer. Wird der Code rechts gekürzt, entsteht eine breitere, weiterhin gültige Klasse.

      Aufbau eines hierarchischen Codes (allgemeines Beispiel)
      Präfix Die Tabelle sagt, welche Sicht gilt
      Jede Ebene Ein Ziffernpaar oder eine feste Zifferngruppe
      Kniff Kürzen = gruppieren ein Präfixfilter erfasst die ganze Familie
      Das Warum

      Ein Code, fünf Zwecke.

      Der Code ist die stabile Verbindung zwischen dem Modell und allem, was folgt: Kosten, Leistungsbeschreibung, Suche, Anforderungen und Instandhaltung.

      Datenkataloge

      Die Klasse sagt, was; die Eigenschaften, wie.

      Ein Datenkatalog verknüpft jede Klasse mit ihren Eigenschaften, Einheiten und einer eindeutigen Kennung im Internet. So versteht eine Maschine den Code.

      Eine Klasse in einem Datenkatalog
      Der Schlüssel Ein Link, kein Text der Code verweist auf eine veröffentlichte Definition
      Klassifikation Gruppiert gleicher Code für die ganze Klasse
      Eigenschaften Beschreiben ein eigener Wert je Objekt
      Die goldene Regel

      Ein System, eine Ausgabe, schriftlich.

      Vor dem Modellieren wird festgelegt: welches System, welche Tabellen, welche Version. Ein Code ohne Ausgabe ist eine Zahl, deren Bedeutung sich ändern kann.

      1Welches Systemeines, für das ganze Team
      2Welche Tabellendie, die die Zwecke verlangen
      3Welche Ausgabefestes Datum oder feste Version
      4Welche Objekteund bis zu welcher Code-Tiefe
      5Wie geprüft wirdvor jeder Übergabe
      ISO 12006-2

      Ein Rahmen, viele Systeme.

      Die internationale Norm liefert keine Codes: Sie legt fest, welche Tabellen ein System haben sollte. Jedes Land füllt sie mit eigenem Inhalt.

      Vier Informationskategorien
      Gültige Ausgabe 2015 Überarbeitung läuft
      Liefert Tabellentitel nicht deren Inhalt
      Ihr folgen Uniclass, OmniClass, CoClass, CCI

      Eine weltweite Klassifikation gibt es nicht. Es gibt Familien aus derselben Norm, fast immer an die Leistungsbeschreibung oder Preisdatenbank des Landes gebunden.

      Uniclass

      Fünfzehn Tabellen, vier Revisionen im Jahr.

      Das britische System ist das lebendigste und kostenlos. Eine Bürotrennwand erhält für jede Sichtweise einen eigenen Code.

      CCI · ISO 81346-12

      Jedes Bauteil klassifizieren und kennzeichnen.

      Die nordische Schule verbindet beides: welcher Typ jedes Objekt ist und eine eindeutige Kennzeichnung, die sagt, welche Funktion es erfüllt, woraus es besteht und wo es sich befindet.

      Revit

      Drei Felder und ein Parameter.

      UniFormat und OmniClass sind ab Werk dabei. Jedes andere System kommt in einen Parameter mit festem Namen und fester Syntax, damit IFC es versteht.

      IFC

      Drei Entitäten tragen den Code.

      System, Code und Verknüpfung mit den Objekten sind getrennt. So kann ein Objekt mehrere Systeme tragen, ohne sie zu vermischen.

      Von der Wand zum System
      Von IFC2x3 zu IFC4 ItemReference → Identification der Code wurde umbenannt
      Achtung Nicht in einer losen Eigenschaft ein Pset „Code“ ist keine IFC-Klassifikation
      Mapping

      Übersetzen ist nicht Kopieren.

      Die Systeme ordnen nach unterschiedlichen Kriterien, eine Eins-zu-eins-Entsprechung gibt es fast nie. Besser jedes System an seinem Platz führen, als eines in ein anderes umzuwandeln.

      Ein Code, mehrere Ziele
      Regel Jedes System an seinem Platzeine IFC-Klassifikation pro System
      Brücken Zuordnungstabellen eigene oder Relationen im bSDD
      Für das Gebäudemanagement COBie: Spalte Category „Code: Titel“
      Was schiefgeht

      Sechs Fehler, die Filter leeren.

      Fast alle entstehen beim Export: Der Code steht im Modell, kommt aber ohne System, unter anderem Namen oder in einem anderen Feld an.

      1Nach Programmkategorienicht jede „Wand“ ist eine Wand
      2Ohne System und Edition„Default Classification“
      3Abweichender Name„Uniclass 2015“ ≠ „Uniclass“
      4Vermischte TabellenPr, wo Ss hingehört
      5Code und Titel zusammenin einem einzigen Feld
      6In einer Eigenschaftstatt als IFC-Klassifikation
      Qualitätsprüfung

      Fünf Fragen an jedes Objekt.

      Ein Code allein genügt nicht. Er muss aus dem vereinbarten System und der richtigen Tabelle stammen, in dieser Ausgabe existieren und zu dem passen, was das Objekt ist.

      Vom leichtesten zum schwierigsten zu automatisieren
      1 · 2 · 3IDSin jedem Prüfwerkzeug
      4Skriptgegen die Tabelle der Ausgabe
      5Auge und Regelnein Mensch prüft Zweifelsfälle
      IDS

      Die Anforderung als Datei.

      Eine IDS sagt: „Jede Wand trägt einen Code aus dieser Tabelle und diesem System.“ Jedes Prüfwerkzeug liest sie gleich – und ein einziger abweichender Buchstabe im Systemnamen genügt zum Scheitern.

      IfcOpenShell

      Gegen die Tabelle prüfen.

      Eine IDS weiß nicht, ob ein Code existiert. Ein Python-Skript vergleicht jeden Code im IFC mit der offiziellen Liste der vereinbarten Ausgabe.
