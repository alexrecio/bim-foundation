      The problem

      Five names for the same wall.

      Every company, program and person names things their own way. Without a common code, neither quantities nor searches add up.

      The same object, five labels
      What happens Nobody adds up the same the "walls" filter misses half of them

      QuantitiesSearchesMaintenanceRequirements
      The way out A code from a common table the name can stay free
      Definition

      Classifying says what it is.

      A classification code groups objects by what they have in common. It does not say which one each is or what it is like.

      Four different pieces of data on the same door
      What makes it useful The same for everyone the same object, the same code, whoever models it
      What it is not A family name each office makes that up
      Facets

      One object, several tables.

      The same door is part of a space, an element with a function, a product that is bought and work that is carried out. Each view has its own table.

      One door, five possible codes
      That is why Faceted several independent tables that are combined
      The question each table answers
      • Where is it? · space
      • What does it do? · element or system
      • What is bought? · product
      You do not need them all Only those each use calls for
      Hierarchy

      A code reads from general to specific.

      Each pair of digits goes down one level. Trimming the code from the right gives a broader class that is still valid.

      Anatomy of a hierarchical code (generic example)
      Prefix The table says which view is used
      Each level A pair of digits or a fixed group of digits
      Tip Trim = group a filter on the prefix catches the whole family

      Data dictionaries

      The class says what; the properties, how.

      A data dictionary links each class to its properties, units and a unique identifier on the web. That is how a machine understands the code.

      The golden rule

      One system, one edition, in writing.

      Decide before modelling which system, which tables and which version. A code without its edition is a number that can change meaning.

      1Which systemone, for the whole team
      2Which tablesthose the uses call for
      3Which editionfixed date or version
      4Which objectsand to what depth of the code
      5How it is checkedbefore each delivery
      ISO 12006-2

      One framework, many systems.

      The international standard contains no codes: it says which tables a system should have. Each country fills them with its own content.

      Four categories of information

      Provides Table titles not their content

      CCI · ISO 81346-12

      Classify and designate every part.

      The Nordic school combines both: what type each object is, and a unique designation that says what function it serves, what it is made of and where it is.

      IFC

      Three entities carry the code.

      The system, the code and the link to the objects are kept separate. That way the same object can carry several systems without mixing them.

      From the wall to the system
      From IFC2x3 to IFC4 ItemReference → Identification the code changed its name
      Watch out Not in a loose property a “Code” Pset is not an IFC classification
      Mapping

      Translating is not copying.

      Systems look at things with different criteria and there is almost never a one-to-one equivalence. Better to keep each system in its own place than to convert one into another.

      One code, several destinations
      Rule Each system in its placeone IFC classification per system
      Bridges Mapping tables in-house, or bSDD relations
      For the facility manager COBie: Category column “code: title”
      What breaks

      Six mistakes that empty your filters.

      Nearly all happen on export: the code exists in the model but arrives with no system, under another name or in another field.

      2No system or edition“Default Classification”
      3Different name“Uniclass 2015” ≠ “Uniclass”
      4Mixed tablesPr where Ss belonged
      5Code and title togetherin a single field
      6In a propertyinstead of an IFC classification
      Quality control

      Five questions for every object.

      Having a code is not enough. It must belong to the agreed system, come from the right table, exist in that edition and match what the object is.

      From easiest to hardest to automate
      1 · 2 · 3IDSin any checker
      4Scriptagainst the edition’s table
      5Eyes and rulesa person reviews the doubtful ones
      IDS

      The requirement, in a file.

      An IDS says “every wall carries a code from this table and this system”. Every checker reads it the same way, and one different letter in the system name is enough to fail.

      IfcOpenShell
