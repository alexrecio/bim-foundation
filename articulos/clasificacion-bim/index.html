      El problema

      Cinco nombres para el mismo muro.

      Cada empresa, programa y persona nombra a su manera. Sin un código común, ni las mediciones ni las búsquedas cuadran.

      Definición

      Clasificar es decir qué es.

      Un código de clasificación agrupa objetos por lo que tienen en común. No dice cuál es cada uno ni cómo es.

      Cuatro datos distintos de una misma puerta
      Lo que la hace útil Igual para todos el mismo objeto, el mismo código, lo modele quien lo modele
      Lo que no es Un nombre de familia ese lo inventa cada oficina
      Facetas

      Un objeto, varias tablas.

      La misma puerta es parte de un espacio, un elemento con una función, un producto que se compra y un trabajo que se ejecuta. Cada mirada tiene su tabla.

      Una puerta, cinco códigos posibles
      Por eso Facetada varias tablas independientes que se combinan
      Pregunta de cada tabla
      • ¿Dónde está? · espacio
      • ¿Qué hace? · elemento o sistema
      • ¿Qué se compra? · producto
      No hace falta usarlas todas Solo las que pide cada uso
      Jerarquía

      Un código se lee de lo general a lo concreto.

      Cada par de cifras baja un nivel. Cortar el código por la derecha da una clase más amplia que sigue siendo válida.

      Anatomía de un código jerárquico (ejemplo genérico)
      Prefijo La tabla dice qué mirada se usa
      Cada nivel Un par de cifras o un grupo de cifras fijo
      Truco Cortar = agrupar un filtro por el prefijo coge toda la familia
      El porqué

      Un código, cinco usos.

      El código es el enlace estable entre el modelo y todo lo que viene después: presupuesto, pliego, búsquedas, requisitos y mantenimiento.

      Diccionarios de datos

      La clase dice qué; las propiedades, cómo.

      Un diccionario de datos une cada clase con sus propiedades, unidades y un identificador único en internet. Así una máquina entiende el código.

      Una clase en un diccionario
      La clave Un enlace, no un texto el código apunta a una definición publicada
      Clasificación Agrupa mismo código para toda la clase
      Propiedades Describen un valor distinto por objeto
      La regla de oro

      Un sistema, una edición, por escrito.

      Se decide antes de modelar qué sistema, qué tablas y qué versión. Un código sin su edición es un número que puede cambiar de significado.

      1Qué sistemauno, para todo el equipo
      2Qué tablaslas que piden los usos
      3Qué ediciónfecha o versión fija
      4Qué objetosy a qué nivel de detalle del código
      5Cómo se compruebaantes de cada entrega
      ISO 12006-2

      Un marco, muchos sistemas.

      La norma internacional no trae códigos: dice qué tablas debería tener un sistema. Cada país las rellena con su contenido.

      Cuatro categorías de información
      Edición vigente 2015 revisión en curso
      Aporta Títulos de tablas no su contenido
      La siguen Uniclass, OmniClass, CoClass, CCI

      Revit

      Tres casillas y un parámetro.

      Trae UniFormat y OmniClass de serie. Cualquier otro sistema se escribe en un parámetro con nombre y sintaxis fijos para que el IFC lo entienda.

      Assembly Code UniFormat sale en el IFC como «Uniformat»
      OmniClass Number Tabla 23 en las familias
      Keynote Nota clave anota planos; no es clasificación IFC
      El parámetro ClassificationCode
      [Uniclass]Ss_25_10_30_35:Gypsum board partition systems
      sistema entre corchetes · código · dos puntos y título · hasta 10 parámetros: ClassificationCode(2)…(10)

      IFC

      Tres entidades llevan el código.

      El sistema, el código y el vínculo con los objetos van por separado. Así un mismo objeto puede llevar varios sistemas sin mezclarlos.

      De la pared al sistema
      Del IFC2x3 al IFC4 ItemReference → Identification el código cambió de nombre
      Ojo No en una propiedad suelta un Pset «Código» no es una clasificación IFC
      Mapeo

      Traducir no es copiar.

      Los sistemas miran con criterios distintos y casi nunca hay equivalencia uno a uno. Mejor llevar cada sistema en su sitio que convertir uno en otro.

      Un código, varios destinos
      Regla Cada sistema, en su sitiouna clasificación IFC por sistema
      Puentes Tablas de correspondencia propias, o relaciones de bSDD
      Para el gestor del edificio COBie: columna Category «código: título»
      Lo que se rompe

      Seis errores que vacían los filtros.

      Casi todos pasan al exportar: el código existe en el modelo pero llega sin sistema, con otro nombre o en otro campo.

      1Por categoría del programano todo «muro» es un muro
      2Sin sistema ni edición«Default Classification»
      3Nombre distinto«Uniclass 2015» ≠ «Uniclass»
      4Tablas mezcladasPr donde iba Ss
      5Código y título juntosen un solo campo
      6En una propiedaden vez de clasificación IFC
      Control de calidad

      Cinco preguntas a cada objeto.

      Que tenga código no basta. Tiene que ser del sistema pactado, de la tabla correcta, existir en esa edición y encajar con lo que el objeto es.

      Del más fácil al más difícil de automatizar
      1 · 2 · 3IDSen cualquier comprobador
      4Scriptcontra la tabla de la edición
      5Ojo y reglasun humano revisa lo dudoso
      IDS

      El requisito, en un fichero.

      Un IDS dice «todo muro lleva un código de esta tabla y este sistema». Cualquier comprobador lo lee igual, y basta una letra distinta en el nombre del sistema para fallar.

      IfcOpenShell

      Comprobar contra la tabla.

      Un IDS no sabe si un código existe. Un script de Python compara cada código del IFC con la lista oficial de la edición pactada.
